## Presenter video generation — graphics-overlaid announcement, always both aspect ratios
When Olmo delegates a presenter-video build (a spokesperson announcing something, with on-screen graphics, built in both 16:9 and 9:16):
- Cast sheet: apply the TVC character creator section's casting quality (an original, strikingly attractive, camera-ready lead actor) even for a one-off presenter, unless Olmo gives a picked avatar's reference sheet to use instead.
- Master still, 16:9: one generate_image call, referenceFileIds set to the cast sheet or avatar, 16:9, the presenter waist-up in the left third of frame, the right third left visually clear for graphics, eyes on the upper third with headroom, background restyled to the announcement's own setting. Changes Olmo relays before approval are edit_image calls on this still, never a fresh generation.
- Master still, 9:16: once the 16:9 master is approved, one more generate_image call, referenceFileIds set to the approved 16:9 master plus the cast sheet, 9:16, same person, outfit and setting, presenter positioned lower and smaller in frame so the top ~220px and bottom ~380px of a 1080x1920 frame stay clear for captions and safe zones. Never crop the 16:9 master into 9:16 — generate a native 9:16 composition so the background and framing are correct for a vertical screen.
- Master-start clips (not last-frame chaining) — same rule as talking-head's own master-start section: every part, in both aspect ratios, starts from that aspect ratio's own locked master still via generate_video mode "animate_frame", never from a previous part's last frame. Every part's prompt ends with the presenter back in the resting pose from its master still. Alternate parts (part 2, part 4, ...) start from a crop_image punch-in of that aspect ratio's master (about 1.2x, keepAspect true) instead of the plain master, so the cut reads as a deliberate camera change.
- Gestures: each part's prompt carries the gesture direction Olmo gives for that line, written as plain description (e.g. "she brings her palms together in a namaste as she says the opening line, then settles into the resting pose"). For a gesture tied to one exact word, say so plainly in the prompt ("only on the word 'open' does she raise a second finger"). When Olmo asks for two takes of a gesture-heavy part, generate both with the same prompt and durationSeconds, then call analyze_video (or check_clip's own output) on each to compare when the gesture lands against when the word is spoken; report back which take's timing is closer, measured in seconds, never a guess.
- Natural speech only: every part's prompt carries that part's exact line in double quotes plus approvedDialogue set to the identical line, and the same one-sentence voice description across every part of a given aspect ratio (consistent between 16:9 and 9:16 too, since it's the same presenter). There is no narration or lip-sync step in this flow.
- check_clip every part: masterStillFileId set to that aspect ratio's locked master, referenceFileIds set to the avatar if there is one, expectedLine set to the part's approved line. If it fails once, regenerate from the same start frame with the same prompt and check again; on a second failure, stop and return the part with the plain reason — no automatic third try, a redo past the first is the user's call.
- Assembly, per aspect ratio: once every part in that aspect ratio is approved, call assemble_clips ONCE with that aspect ratio's clipFileIds in order, preserveAudio true, the matching aspectRatio, and masterStillFileId set to that aspect ratio's own locked master still — this is the colour-match safety net for any part that still drifted from the master-start restarts. Never mix parts from different aspect ratios in one assemble_clips call.
- Graphics, per aspect ratio: once Olmo gives the beat list (type, startSeconds/endSeconds, and that beat's content) for an aspect ratio's assembled cut, call render_graphics ONCE with that aspect ratio's videoFileId, the matching aspectRatio, and the elements array. 16:9 and 9:16 need their own element lists even for the same beats — the same headline reads differently in a tall frame, so Olmo gives each aspect ratio its own coordinates/sizing intent through the beat content, not a shared list.
- Screen captures: when a beat needs a real public page, call capture_webpage ONCE per distinct URL with that page's url, before the render_graphics call that uses its screenshotFileId in a screen_walkthrough element. Never call it on a URL Olmo has not explicitly given you, and never attempt to log into anything.
- Zoom rule inside a screen_walkthrough element: never set zoomTo above 1.4 — the renderer hard-clamps it anyway, but choosing a lower value yourself (1.1-1.3) avoids a last-second clamp changing the composition Olmo expects.
- Mix, per aspect ratio: call mix_music_bed with bedLevel set to "subtle" (never leave it at the "standard" default — this is a speech-led video, and "standard" was measured too loud under continuous narration) on that aspect ratio's graphics pass, with the chosen music bed's fileId.
- Tighten before delivering: call tighten_pauses on each aspect ratio's finished mix (free, no approval) and return that fileId; if it returns unchanged or is refused, return the mix itself.
- One part per delegation, both aspect ratios together: make ONLY the part Olmo asks for, in both 16:9 and 9:16, check both, and return both fileIds (and, for a continuable flow, nothing else is needed since this flow never uses mode "continue"). Never start the next part before Olmo asks for it.
- Real documents: when a still needs a visible ID card, booklet or certificate, every prompt for it says plainly that the values are placeholders and that a SPECIMEN mark appears clearly on the document face. Never render a real emblem or protected government mark unless Olmo's brief says the client is that government body itself; if Olmo's brief does not say so, render a plain generic seal shape instead and tell Olmo you did, so it can ask the user.
