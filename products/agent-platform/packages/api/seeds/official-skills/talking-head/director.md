## Talking-head generation — one continuous presenter, narration-first pipeline
When Olmo delegates a talking-head ad build (single continuous presenter speaking to camera, script-driven, not a multi-beat storyboard):
- Cast sheet: same as UGC character generation above — one generate_image call with referenceFileIds set to the product photo's fileId if one exists, otherwise no reference. Do not pass identityAnchor on this call.
- Narration: call generate_narration ONCE with the full script and the user's chosen voiceId (and language, if Olmo's brief specifies one other than English) — never split the script into per-clip segments. As soon as it succeeds, tell Olmo the returned fileId and durationSeconds so Olmo can lock both into working memory's Locked Reference Artifact IDs alongside the cast sheet. Every later step in this flow must use that locked fileId and durationSeconds, restated to you by Olmo in each delegation message — never call generate_narration again for the same ad unless the user has explicitly changed the script.
- Clip count: compute clipCount = Math.ceil(durationSeconds / 10), capped at 3. If clipCount would exceed 3 (more than 30 seconds of narration), tell Olmo the script needs to be shorter rather than proceeding.
- Clip durations: split the narration's total duration across clipCount clips as whole-second durations that sum to Math.ceil(durationSeconds), front-loaded toward 10 seconds each, but NEVER let any clip's duration drop below 3 seconds — generate_video's own floor. If a clip would otherwise be too short, rebalance the split evenly across clips instead (for example, a 21-second narration splits as 7+7+7, not 10+10+1). Each individual clip's durationSeconds must stay within generate_video's own 3-10 second range.
- Per-clip stills: generate_image per clip, referenceFileIds set to the cast sheet's fileId, identityAnchor set with the terseTag/styleLock Olmo gives you. Every still must show the presenter's face clearly visible, front-facing or near-front-facing, and alone in frame — never turned away, never out of frame, never replaced by a product-only shot. If a product photo exists, the product may appear alongside the presenter, never in place of them. If the product is visible in a still, apply the UGC character section's wordmark-handling pattern unchanged: spell the brand name letter-by-letter in the prompt, call analyze_image to verify it rendered correctly, and tell Olmo plainly on a mismatch rather than silently retrying.
- Per-clip silent video: generate_video, mode "animate_frame", off each approved still, at that clip's computed duration. Do not pass approvedDialogue and do not write any quoted dialogue in the prompt — these renders are silent; the narration audio is added later via lip-sync, not native speech. Apply the Motion craft section's rules with one exception here: only the LAST clip should pin to a final held state. Every other clip should end on sustained motion, not a hold, so the cut between clips reads as a continuation under the continuous narration track rather than a series of separate paused shots.
- Issue generation calls strictly one at a time: call generate_image or generate_video for one clip and wait for that call's result before issuing the next generate_image/generate_video call. Never issue two generation calls in the same step.
- Assembly: after all clips in this ad are generated and approved, call assemble_clips ONCE with clipFileIds in order, targetDurationSeconds set to the narration duration and fileId Olmo gave you in this delegation message, and aspectRatio set to the same aspectRatio used for the per-clip video renders.
- Lip-sync: call lipsync ONCE — videoFileId set to the assembled clip's fileId, audioFileId set to the narration fileId Olmo gave you in this delegation message. Do not call lipsync per-clip; it runs exactly once per ad, after assembly, never before. Default to the fal-ai/latentsync model (cheaper, fully managed) unless the user has explicitly asked for higher fidelity, in which case use sync-2.0.
- QA: call analyze_audio (mode "deep") on the lip-synced result and compare its transcript to the original script, same as template cloning and UGC character generation — flag any meaningful mismatch rather than presenting it as matching.
- Tell Olmo plainly that this ad has a deliberate visible cut where clips join (per the motion-craft exception above), since the narration itself stays continuous across it — this is expected, not a defect to explain away.
- Narration delivery: when calling generate_narration, set emotion and speed from Olmo's delivery (if Olmo gave none, pick from the ad's tone: enthusiastic at 1.05 for UGC or testimonial, content at 1.0 for wellness or calm, confident at 1.0 for premium or a pitch). Before the call, make sure the script is written for the ear: numbers and symbols as spoken words ("a hundred percent", never "100%"), punctuation where a person would breathe, no <break> tags. Do not otherwise rewrite the script's words.
- Narration direction: pass Olmo's voice direction to generate_narration as direction (never inside the script). If Olmo gave none, write one from the ad's tone: who is speaking, to whom, and how, ending with "never polished" for UGC. Keep any vocal tags (<breath>, <short pause>, <laugh>, <sigh>) Olmo's script carries, at most two.
- Master still and per-clip frames (this replaces the per-clip generate_image line above): when Olmo asks for the master still, make ONE image: referenceFileIds set to the avatar (or cast sheet), the prompt keeping the avatar's exact outfit, hair and accessories and saying plainly "replace the reference photo's background with <the ad's location>", 9:16, face clearly visible and front-facing. Changes Olmo relays before approval are edit_image calls on the master still. Once Olmo gives you the locked master still, build each clip's start frame from it without generating: clip 1 uses the master still itself; clip 2 is crop_image with framing "close-up" and keepAspect true; clip 3 (if any) is crop_image with framing "half-body" and keepAspect true. Never call generate_image for a later clip's frame unless Olmo says the user asked for a different scene.
- Lip-sync fallback: if lipsync is refused (LIPSYNC_NOT_CONFIGURED or any other reason), call mux_beat_audio with videoFileId set to the assembled video's fileId and audioFileId set to the locked narration's fileId, and return that muxed fileId as the deliverable, telling Olmo the lips are not synced. Never call lipsync again after a LIPSYNC_NOT_CONFIGURED refusal. When the assembled video was made with audioFileId (it already carries the narration — the normal case), do NOT call mux_beat_audio: return the assembled video itself as the deliverable. mux_beat_audio is only for an assembled video that has no sound.
- Assembly with sound: when calling assemble_clips, also set audioFileId to the locked narration's fileId, so the assembled video already carries the voice and is a finished video on its own. Lip-sync then runs on it to fix the mouth; if lip-sync is refused, return the assembled video as the deliverable (no separate mux step needed).
- Natural-speech mode (the default when Olmo sends an approved script and a voice description instead of a narration fileId): for each clip, its start frame is built from the master still as above; call generate_videos with one item per clip, mode "animate_frame", durationSeconds set to that line's length (its word count divided by 2.7, rounded up, between 3 and 10), the prompt describing the motion and including that clip's exact line in double quotes plus the same voice description sentence for every clip (e.g. "She speaks in a warm young Indian woman's voice, mid-20s, light Hinglish accent, casual and natural."), and approvedDialogue set to that same exact line. Never let a clip speak anything but its approved line. Then call assemble_clips with preserveAudio true (no audioFileId, no targetDurationSeconds), and return that one video as the deliverable. Do not call generate_narration or lipsync in this mode.
- Natural-speech performance: every clip's prompt also carries that clip's performance from Olmo — the emotion, energy, facial expression and gesture while saying the line (e.g. "she says it genuinely excited and a little giddy, eyebrows up, a real smile, a small laugh mid-line, leaning toward the camera on the last words"), written as plain description outside the quoted line. If Olmo gave none, take it from the ad's tone: UGC means visibly excited, warm and expressive, never neutral or presenter-calm. Same voice description in every clip; only the performance changes per line.
- Natural-speech lines are plain spoken words: strip any <...> vocal tags from a line before quoting it (and from approvedDialogue identically), and turn each into a performance note in that clip's prompt instead (e.g. <laugh> becomes "she laughs lightly before the last words").
- Clip chaining (this supersedes the crop rule for later clips above): by default every clip after the first starts from the previous clip's real LAST frame. So generate the clips one at a time with generate_video (never as one generate_videos batch): clip 1 from the master still; then extract_frame (at "last") on clip 1 and use that image as clip 2's startImageFileId; then the same from clip 2 for clip 3. This keeps the same face, pose, outfit, room and light, so the cut is nearly invisible. Use the other two start frames only when Olmo says the user asked for them: crop_image (framing "close-up", keepAspect true) on the master still for a deliberate punch-in on a line (emphasis, the punchline, the call to action); or a new generate_image still from the master still plus the avatar's reference sheet for a deliberately different angle, a new place or an outfit change.
- Check every clip before using it: right after each clip is generated (and before extracting its last frame for the next clip), call check_clip with clipFileId, masterStillFileId set to the locked master still, referenceFileIds set to the avatar if there is one, and expectedLine set to that clip's exact approved line (omit for a silent clip). If passed is false, regenerate that clip once from the same start frame with the same prompt and check it again. If it fails a second time, stop: do not join anything, and tell Olmo plainly what failed (a different-looking person, or a different line) so Olmo can tell the user.
- When the ad has a product photo, also pass it to check_clip as productFileId, so a clip where the product's shape, colour or printed/embroidered text changed (or got garbled) fails and is regenerated like a different-person clip.
- Presenter from a plain uploaded photo (not a saved avatar, so it has no reference sheet): before the master still, make a reference sheet of that person with the Avatar creation reference-sheet prompt (one generate_image, 16:9, referenceFileIds set to the photo only), then use both the photo and that sheet as referenceFileIds for the master still. Say so in the plan as one extra image. Saved avatars and library avatars already carry their sheet; never make another for them.
- Continuation is the default way to build a multi-clip talking-head (supersedes clip chaining above, which becomes the fallback): clip 1 is generate_video mode "animate_frame" from the master still and returns an interactionId; each later part is generate_video mode "continue" with continueFrom set to the previous part's interactionId, its own approved line in double quotes plus approvedDialogue, the same voice description, that part's performance, and durationSeconds set to the line's word count divided by 2.7, rounded up (3-10). End every part's prompt with "then he/she stays quiet, smiling at the camera, for any remaining time." so no extra words are invented. Each continue result is the WHOLE video so far: run check_clip on it with expectedLine set to the new part's line; if it fails, continue again from the last GOOD part's interactionId (once), and stop if it fails again. The final continue result is the finished ad — no assemble_clips. Fall back to clip chaining (extract_frame + animate_frame per clip, then assemble_clips with preserveAudio) only when a continue call is refused or errors, or when Olmo says the user asked for a punch-in, a different angle, place or outfit, or to redo just one middle part.
- One part per delegation (supersedes building every part in one go above): make ONLY the part Olmo asks for. For part 1: generate it, run check_clip, and return its fileId and interactionId to Olmo, then stop — do not continue on your own. For a later part, Olmo gives you the interactionId to continue from and that part's approved line: continue, check, and return the new fileId and interactionId. Never start the next part before Olmo asks for it.
- If a part still fails check_clip after its one retry, do not stop silently and do not hide it: return that part's fileId and interactionId with the plain reason (e.g. "a second bottle appears in her other hand for a moment"), so Olmo can show it and let the user decide.
- Product in hand: when the presenter holds the product, every part's prompt names the hand and says she keeps holding the one bottle in that same hand the whole time, with no second bottle — Omni otherwise swaps hands or duplicates the product in the first second.
- Product label on the master still: if analyze_image says the brand name came out misspelled or garbled, say so plainly in your reply with what it reads (e.g. "the label reads Minimaliat, not Minimalist"), so Olmo tells the user before they approve the still — never describe the still as exact when it is not.
- Clip checks always carry every input (masterStillFileId, referenceFileIds when there is an avatar, expectedLine, productFileId when the product is in it). If check_clip is refused or errors, call it again once with exactly the same inputs; never leave inputs out to get a pass. If it still cannot check, say plainly that the part is unchecked.
- Real places, not showrooms: every still's setting reads as a real place someone actually lives in or uses and would happily film in — tidy but lived-in, pleasant and inviting, never messy or gloomy. Write it plainly ("in his kitchen", "on her bed in her bedroom") and add: two or three everyday things that belong in that room and fit the presenter, the product and where the audience lives, real materials with a little honest wear, soft daylight from a window mixed with warm indoor light, and the background slightly soft the way a phone camera renders it. Pick different everyday things for each ad, never the same list. Never describe the place as modern, aesthetic, luxury, cinematic, perfect, pristine or spotless, and never ask for studio lighting. A setting the user describes still wins.
- No automatic redo (supersedes every "regenerate once" on a failed check above): when check_clip fails, do not regenerate on your own — a redo is the user's choice and costs money. Stop and return the part's fileId (and interactionId) with the check's reason in plain words (e.g. "the label on the bottle looks garbled", "she says a different word at the end"), so Olmo shows it and lets the user decide.
- Tighten before delivering: once the ad is finished (the last approved continue result), call tighten_pauses on it (free, no approval) and deliver the fileId it returns — it cuts dead air at the start and end and shortens long pauses, so viewers never sit through a silent moment. If it returns unchanged or is refused, deliver the original.
- Auto mode (supersedes "One part per delegation" and "Clips before voice" when Olmo's brief says "auto: continue"): make every part or scene Olmo asked for in this delegation, checking each one, and finish the ad. Stop early only when a check fails or a tool refuses with SHOW_FIRST: then return what was made and the problem to Olmo.
- Last-frame clips are the default again (supersedes "Continuation is the default" above; continuation becomes the fallback). In a side-by-side test on the same script, the user picked clips chained from the last frame over continuation "easily". Build each part as its own clip:
  - Part 1: generate_video mode "animate_frame" from the master still.
  - Each later part: extract_frame (at "last") on the previous approved part, then generate_video mode "animate_frame" with that frame as startImageFileId. Its prompt carries:
    - that part's line in double quotes, with approvedDialogue set to the identical line;
    - the same one-sentence voice description and the same one-sentence sound description as part 1 (e.g. "Recorded on her phone in her bathroom: soft room echo, the same in every clip");
    - that part's performance;
    - the ending "then she/he stays quiet, smiling at the camera, for any remaining time."
  - check_clip every part as usual, and from part 2 on add soundReferenceClipFileId set to part 1's fileId, so a part whose voice or room changed fails.
  - Once every part is approved: call assemble_clips ONCE with all parts in order, preserveAudio true and the same aspectRatio, then tighten_pauses on the result, and deliver that.
  - "One part per delegation" still holds: for a later part, Olmo gives you the previous approved part's fileId (not an interactionId).
  - Use mode "continue" only when Olmo says the user asked for one unbroken take, or when a part fails the sound check and the user chooses to carry the same voice on.
- A logo or print on clothing (the product is a shirt, cap or other wear with a printed logo): every still's prompt says the logo from the reference is a plastisol screen print on the centre of the chest (or the spot the user named), about the size of a palm, and that it is a print on a worn shirt, not an image placed on top: the shirt's creases and wrinkles run straight through the print, its colours are a little muted and darker where the fabric folds or falls into shadow, the fabric shows faintly through the ink, there is fine cracking from washing, and the print curves over the body with the shirt. Every clip prompt adds that the logo stays a screen print in the fabric, creasing and moving with the shirt. Tested 2026-10-05: without this the logo came out as a glossy sticker pasted on the chest.
- End card (after tighten_pauses, supersedes delivering the tightened ad directly): when the user gave a real product photo or logo, call composite_end_card with videoFileId set to the tightened ad, productPhotoFileId set to that real photo (never an AI-made still), the ad's aspectRatio, and holdSeconds 1.5, so the last frame holds and the card dissolves in after the last word. Deliver the fileId it returns. Skip this only when there is no real product photo or the user asked for no end card; if it is refused, deliver the tightened ad.
